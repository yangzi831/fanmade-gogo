# fanMade GoGo!

Made by fans. Shared with fans.

最新改动：CAN 横幅只在物料发现页展示；分类为“全部、音乐节、剧场、演唱会、活动、其他”，活动入口由数据库生成。演示名称改为具体物品。上传加入压缩／缩略图，发现页加入后台分页。免费方案、额度、限制和真实进度见 [docs/FREE_HOSTING.md](docs/FREE_HOSTING.md)。源码保存到私有仓库 [yangzi831/fanmade-gogo](https://github.com/yangzi831/fanmade-gogo)；Supabase Free 项目 fanmade-gogo（Singapore）已创建；配置位置、建表与私有存储步骤见 [docs/SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md)，真实云端连接、初始化和双账号验证已通过，结果见 [docs/CLOUD_VERIFICATION.md](docs/CLOUD_VERIFICATION.md)；公网部署待完成。

本轮按用户提供的桌面／手机参考图更新了发现、我的、记录页面，并接通真实收藏与 CAN 活动横幅。最新页面映射、默认规则及验证结果见 [docs/REFERENCE_REDESIGN.md](docs/REFERENCE_REDESIGN.md)；之前的分阶段差距见 [docs/LATEST_REQUIREMENTS.md](docs/LATEST_REQUIREMENTS.md)。

面向音乐节、音乐剧等现场的多制作人物料分享站。手机优先，也支持桌面。React + TypeScript + Vite；Express 5；SQLite；图片保存到服务器磁盘。代码、示例 SVG 插画均在本项目中，业务数据不依赖 GitHub，也不依赖浏览器 localStorage。

## 本地启动

需要 **Node.js 22.10 或更高的 22.x 版本**及 npm。推荐 Node 22 的最新维护版本。使用 Node 内置 SQLite，启动脚本已包含 `--experimental-sqlite`；首次启动出现实验性提示属于当前运行时的已知行为。

```powershell
npm ci
npm run seed
npm run build
npm start
```

打开 **http://localhost:3001**。开发时运行 `npm run dev`，访问 **http://localhost:5173**，前端和接口均支持热更新。通常无需 `.env`；需修改配置时参考 `.env.example`。`npm run seed` 仅首次创建演示数据，发现任意演示账号存在时不会覆盖已有数据。

全新演示数据包含 **2 位制作人、3 场示例活动、7 件示例物料**，另收录真实的 **楠溪江·2026 Can Festival PT.2** 活动和用户提供的海报。CAN 初始没有物料，不能把示例物料当成这场演出的作品。演示账号与活动均在界面明确标记，操作会真实写入数据库。全新正式环境不要执行 seed；自行注册账号。登录页只有检测到演示账号时才显示演示凭据。

已有数据库可运行 `npm run feature:can` 收录海报活动，重复执行不会重复创建同一活动、复制库存或覆盖账号。启动会自动迁移到数据库版本 6，已有库迁移前生成备份，仅修改未编辑的标记演示名称和旧活动分类；原数据、账号和库存保留。

### 建议试用顺序

1. 主导航是“发现、记录、我的”。“发现”内部切换物料／活动／制作人，浏览公开数据；活动搜索可找到空活动。CAN 横幅打开真实活动，竖版海报可点开完整查看。
2. 打开“我的”，登录 `wuwei`，编辑头像昵称；“管理我的物料”进入独立的物料／收到的申请／设置管理区。
3. 用另一浏览器或隐私窗口登录 `xiaoyu`，打开 `/u/wuwei` 选择物料并预约。“记录 → 我领取的”自动保存登录状态下的新预约。
4. 贴纸盒在“管理 → 收到的申请”查码并标记领取；两边刷新应看到同一状态，贴纸盒“记录 → 我发出的”也展示同一数据。
5. 任一账号点击“发布物料”直接进入表单，可不关联活动；也可搜索、加入已有活动或核对可能重复的活动后添加，选择活动保留未保存的物料输入。
6. 连续添加、保存草稿、预览、发布。首次保存后这批库存固定属于所选活动或日常清单。跨活动请明确分配真实份数，不能把一份库存复制使用。
7. 公开主页 `/u/用户名` 展示跨活动与未关联活动的公开物料。换账号浏览不影响主页归属，未公开物料不出现在发现流。
8. 在“设置 → 管理全站活动库”（贴纸盒管理员）添加空活动；活动目录搜索能找到，发布第一份公开物料后自动进入默认活动目录。
9. 原暂停截止、互换确认、手动登记、整单取消和分享继续可用。点击爱心收藏物料、活动或制作人，在“我的收藏”查看；“关注的活动”是收藏活动，不发送通知。点赞计数暂未实现。
10. 历史免登录预约凭原专属链接查询；持链接登录后可以明确保存到我领取的，不按昵称／联系方式自动匹配。

### 共享活动与管理权限

原首页活动入口来自 **SQLite 活动表中的 seed 演示记录**，不是硬编码卡片。现在迁至“活动”页，仍从数据库读取并以全站共享活动汇总，默认仅展示尚未结束且至少有一件公开物料的活动，按日期排序；搜索覆盖空活动和已结束活动。

- `/e/活动UUID`：全场公开物料卡片，可按制作人、类型和领取方式筛选。
- `/e/活动UUID/by/用户名`：该制作人在本场的独立清单，可直接分享、生成二维码和预约。
- `/u/用户名`：该用户跨活动及日常物料的稳定公开主页。
- `/u/用户名/collection`：未关联活动的公开物料清单。
- `/me`：统一账号与个人入口；`/manage`：独立管理区；`/publish`：直接发布；`/records`：双向预约／交换记录。旧 `/admin` 自动转到新入口。
- “管理全站活动库”：站点管理员添加或编辑共享活动资料，也可先添加空活动。普通制作人可以搜索加入，也可核对重复后添加缺少的活动；共享元数据后续修改由站点管理员负责。

现有本地库迁移后的管理员为 **wuwei**。全新空库的首个注册账号自动成为站点管理员；之后注册的账号为普通制作人。管理员的活动资料权限不包含其他制作人的私密预约权限。

完整默认规则、迁移与待确认项见 [docs/SHARED_EVENTS.md](docs/SHARED_EVENTS.md)。

手机通过同一局域网访问时，用电脑的局域网 IP 替代 localhost，并把 `.env` 中 `APP_ORIGIN` 设为手机实际访问的完整来源，例如 `http://192.168.1.20:3001`。重启服务，允许系统防火墙访问对应端口。普通 HTTP 局域网中复制链接可能受浏览器权限限制，此时可从地址栏手动复制。

- 无预约现场发放／互换登记，选填昵称、联系方式、地点和备注，仅扣未预留库存，私密记录与幂等保护。
- 完整／部分／单件公开分享，三种配色、实时预览、PNG 下载、复制链接及文案；分享引用原库存。
- 手机、平板和桌面自适应；桌面多列卡片、侧栏筛选、发布和分享编辑／预览并排。
- 同一活动、同一制作人的多件物料整单预约；免登录填写信息，成功预留库存并生成领取码。跨制作人分别预约。
- 不可猜测的私密查询链接；查看、刷新状态与整单取消。
- 独立互换申请表，文字说明与可选图片，制作人确认/拒绝。
- 制作人查看联系人、备注、数量，按领取码、昵称或联系方式搜索、按状态筛选，取消和整单领取。
- 总量、可预约、已预留、已领取统计；库存事务、状态转换、幂等提交与重复操作保护。
- 服务端所有管理接口均校验归属。公开浏览接口不返回联系方式、私密备注或预约列表。
- 互换上传图片默认私密，按对应制作人会话或该预约的私密凭证授权访问。

本版**不包含**社交关注、聊天、推荐、支付、通知发送、验证码、找回密码、逐件核销、撤销领取、自动过期释放、物料删除。没有推荐算法。收藏已经持久化；点赞计数、多图、必选品、普通领取新确认状态、软删除和历史快照等缺口见最新阶段文档。

## 持久化和项目结构

```text
server/db.mjs       SQLite 表结构及事务
server/rules.mjs    集中的预约、库存与状态规则
server/materials.mjs 批量发布、手动发放及分享范围
server/availability.mjs 草稿、暂停和截止规则
server/events.mjs   共享活动搜索、重复检测、加入与公开汇总
server/accounts.mjs 统一账号双向记录、日常库存范围与发现流
server/event-identity.mjs 活动身份规范化与结束时间
server/app.mjs      HTTP 接口、身份与归属检查、上传访问控制
server/seed.mjs     显式执行的演示数据初始化
src/               React 页面、移动适配样式、API 类型
public/assets/     本地原创示例插画
tests/             多进程接口集成测试
data/              运行时数据库与图片（不进入 Git）
docs/              默认规则、部署、测试与参考项目说明
```

SQLite 文件为 `data/materials.sqlite`，启用 WAL，上传文件在 `data/uploads/`。两者必须一起持久化与备份；只推送代码不会保存用户数据。浏览器 sessionStorage 仅保存未提交的选择和幂等键，实际账号、物料、图片、预约均在后端。

## 在线部署与后续配置

当前版本已可在本地完整运行，**尚未发布到互联网**。最简单的部署是单台 Linux VPS + Docker Compose 持久化卷 + Caddy HTTPS，无需外部数据库、认证或对象存储服务。不要直接把此 SQLite 版本部署到临时磁盘的函数环境或只托管静态文件的平台。

详细步骤见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。上线前需要提供服务器、域名及 DNS，配置 `APP_ORIGIN` 和 HTTPS，部署持久化卷并安排备份；新环境不导入演示数据。Docker 配置已准备，但当前环境未实际进行云部署。

第一版默认规则与后续需求清单见 [docs/RULES.md](docs/RULES.md)。开源参考核对见 [docs/REFERENCES.md](docs/REFERENCES.md)。
