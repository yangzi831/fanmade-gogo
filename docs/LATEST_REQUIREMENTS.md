## 本轮边界

只交付第 1 阶段：四项主导航、统一账号入口、物料发现与共享活动分离、“我的”及个人资料、独立管理区、共用双向记录入口、公开主页与首次发布入口。沿用已有库存与预约功能，不把第 2–5 阶段未实现的能力伪装为已完成。

新的普通领取“待确认但已预留”状态、每次限额、必选物料、软删除和历史快照在对应阶段集中修改并验证。本轮保留原免费预约直接待领取、原累计联系方式限额的旧规则，页面与交付说明标明过渡状态。

后续依次实施第 2 阶段发布与互动、第 3 阶段领取清单与备注、第 4 阶段状态与软删除、第 5 阶段品牌分享与响应式收尾、第 6 阶段小程序。本轮结束后停在阶段边界。

## 第 1 阶段交付

- 主导航为“发现、活动、记录、我的”。手机底部导航，桌面顶部导航；发布按钮始终明显。没有个人版、摊主版或开店流程。
- 发现页读取 `/api/materials`，跨发布者展示真实公开物料，支持关键词、类型、领取方式筛选。卡片进入正确发布者的详情和主页；隐藏物料与未公开清单不进入发现页。
- 活动目录移至 `/events`，沿用数据库生成入口、空活动搜索、添加前相似提醒、多人加入、活动内发布者／类型／领取方式筛选。旧版以配色推断音乐／剧场的筛选已移除，避免把样式当业务分类。
- `/me` 集中个人资料与头像昵称编辑、管理我的物料、公开主页、收藏点赞入口、双向记录、退出登录。
- `/manage` 是独立管理区，内部“物料、收到的申请、设置”，桌面侧栏、手机标签和返回入口。原编辑、草稿、批量添加、暂停、现场登记和分享继续可用，管理库存目前按活动／日常清单查看。
- `/publish` 直接打开连续发布表单，默认可不关联活动；填写过程中搜索或加入已有活动，保留物料输入。首次保存后固定这批物料的库存范围，避免切换活动后复制库存或修改错清单。
- `/u/用户名` 稳定展示该用户跨活动和日常物料，可按活动筛选。不会随访问者的登录账号改变。公开主页不堆放管理按钮。
- `/records` 的“我领取的”读取账号关联的预约，“我发出的”和管理区“收到的申请”读取同一份预约表、复用同一管理组件；支持筛选、搜索、刷新及受权访问记录详情。
- 登录状态下的新增预约由服务端绑定当前账号，忽略伪造的领取者账号参数。双方账号可以查看同一状态、私密联系方式及互换图片，其他用户无权访问。
- 历史免登录预约仍通过原私密链接查看。持链接者登录后，可明确点击保存到“我领取的”；不会按相同昵称、联系方式自动归属。绑定后不能被其他账号再次认领。
- 新页面的品牌名称、标题和品牌句已更新为 fanMade GoGo!；分享 PNG 品牌和主页分享图片留在第 5 阶段统一更新。收藏与点赞入口如实显示尚未开放，没有模拟列表或伪造按钮。

## 本轮架构与默认规则

1. 保留 React／Express／SQLite／本地图片持久化。数据库版本从 2 升至 3，新增预约领取账号与日常库存范围；旧数据迁移前自动生成 `data/before-unified-account-时间戳.sqlite`，请与上传目录一起妥善保存。
2. 为兼容已有非空 `event_id` 和事务规则，每位用户的未关联活动物料在底层使用一个唯一内部库存容器，并以 `personal_collections` 显式标记。它不是共享活动：目录、重复搜索、活动加入和全场聚合均排除它。外部使用 `/u/用户名/collection` 和 `/u/用户名/m/物料ID`。
3. 各活动和日常清单使用明确独立的库存分配。本轮不提供“同一份库存自动复制到多场活动”的功能；发布者必须分配真实份数。复用物料资料的便捷操作留待第 2 阶段，不会因为加入活动自动产生物料或库存。
4. 浏览不要求登录。登录后既能发布又能领取；免登录预约能力保留。账号详情链接需双方登录授权，随机领取码本身不能用来获取私密详情。
5. 一个访客预约只可绑定一个领取账号。重试原提交不会重绑账号、创建第二份预约或再次扣库存。登录后取消原预约仍使用同一个库存事务。
6. 暂不改变既有预约状态机、限领和历史数据结构：免费提交即预留并直接待领取；互换接受后预留；原联系方式累计限领仍生效。新的普通领取待确认、每次限额和必选品将在对应阶段替换，不能把本轮当作全部最新业务规则已实现。
7. 页面查询和刷新展示最新共享状态；本轮没有实时推送。原始活动入口是 SQLite 中的已标记演示记录，非写死按钮；新的发现物料流也直接查询数据库。

## 实际验证（2026-10-14）

`npm test` **27 组通过**，`npm run build` 通过。原 21 组库存、并发、权限、活动、发布及分享回归保留，新增 6 组覆盖：

- 同一账号同时发布和领取、双方读取同一记录，第三方无法读或取消；
- 访客记录仅凭原私密凭证主动归属、重复认领与幂等重试不改账号；
- 未关联活动的公开链接、库存事务、不可被别人加入、不会污染活动目录；
- 发现流和公开主页的发布状态及账号隔离；
- 互换私密图片允许双方账号访问，拒绝第三方及匿名访问；
- 版本 2 数据升级保留原账号密码、库存、预约备注、明细和备份，重复启动不重复迁移。

浏览器使用 Playwright 的三个独立会话连接 **同一个 localhost:3002 后端及临时 SQLite**，完成：

1. 无为、小屿分别登录。小屿从无为公开清单选择物料、填写并提交预约。
2. 无为“管理 → 收到的申请”看到领取码并完成交接；无为“记录 → 我发出的”和小屿“记录 → 我领取的 → 已完成”显示同码、同一已领取状态。
3. 新注册测试账号不经开店流程直接发布日常物料；再搜索加入现有活动，切换后名称保留，保存草稿后范围锁定，成功发布；公开主页同时展示两种范围。
4. 小屿打开该新账号日常清单并成功预约，该预约进入账号的“我领取的”。
5. 7 个页面（发现、活动、我的、管理、发布、记录、公开主页）分别检查 **320／390／768／1024／1440 px，共 35 次宽度检查**，未发现页面横向溢出。已查看桌面发现、管理及手机我的、管理、发布截图；管理区手机收起全站底部导航。
6. 修复浏览器发现的注册用户名 HTML pattern 在新正则模式中的转义问题；复测合法用户名通过、非法字符被拦截，控制台无错误。另补查有实际物料的管理页、收到的申请和我发出的记录，共 15 次五档宽度检查，无横向溢出。

浏览器临时数据未写入 `data/`。现有本地库迁移前后对比：2 个账号、3 场活动、7 件物料、2 条预约、0 条现场登记及每件库存保持一致。生成迁移备份，版本为 3。

截图在忽略目录 `output/playwright/gogo-*.png`，自动化测试为 `tests/accounts.test.mjs`。浏览器视口检查不等于手机真机验收；微信长按二维码识别、iOS／Android 相册保存、软键盘和安全区仍需设备测试。本轮未新增微信或云服务接入。

## 启动与多人试用

已有项目直接 `npm run build` 后 `npm start`，打开 `http://localhost:3001`。首次安装先 `npm ci`；现有库无需重新 seed。演示账号 **wuwei、xiaoyu**，密码均为 **Demo2026!share**。全新空库仅试用时运行 `npm run seed`，正式上线不导入演示数据。

使用两个浏览器或普通／隐私窗口连接同一地址：窗口 A 登录无为，窗口 B 登录小屿；B 浏览 `/u/wuwei` 预约，A 在收到的申请中查码并完成，B 在我领取的刷新查看；A 的管理区和我发出的应始终一致。B 也能直接发布自己的物料，A 不能修改。测试会真实保存，请使用本地演示库或另设 `DATA_DIR`。

本地无需外部服务；在线仍需域名、HTTPS、常驻 Node 22 服务、持久磁盘（SQLite 与 uploads）、`APP_ORIGIN`、备份和反向代理。参见 `docs/DEPLOYMENT.md`。GitHub 只存代码；小程序属于第 6 阶段，后续通过接口复用真实后台。
