# 第一版默认规则与待定问题

以下规则是当前实现，不是未实现的规划。核心逻辑集中在 `server/rules.mjs`、`server/materials.mjs` 和 `server/availability.mjs`。本次发布、现场登记、截止及分享的详细默认规则见 [MATERIAL_STUDIO.md](MATERIAL_STUDIO.md)。

## 账号、页面和公开范围

- 一个网站承载所有制作人。活动全站共享，同一活动可有多位制作人；每位制作人独立拥有自己的物料、领取说明和预约管理权限。共享活动资料由站点管理员维护，详细规则见 [SHARED_EVENTS.md](SHARED_EVENTS.md)。
- 个人链接使用不可修改的用户名：3–30 位小写字母、数字、下划线、短横线。昵称可修改。
- 公开页面按 URL 指定制作人或活动读取，不根据当前登录账号替换内容。
- 活动库记录公开，可搜索空活动。制作人可关闭自己的清单公开状态，关闭后该清单不可浏览和新建预约，已有查询凭证仍可查阅及取消；其他制作人不受影响。
- 用户简介和物料说明按纯文本渲染；上传只接受不超过 5 MB 的 JPG、PNG、WebP，并检查文件签名；不接受上传 SVG。
- 注册密码至少 10 位，使用 bcrypt 哈希；登录会话 7 天，没有滑动续期。退出即删除对应服务器会话。

## 库存与预约

| 动作                | 已预留 | 已领取 | 规则                                           |
| ------------------- | ------ | ------ | ---------------------------------------------- |
| 免费预约成功        | +数量  | 不变   | 所有物料同时成功，任何失败则整单回滚           |
| 提交互换            | 不变   | 不变   | 进入待确认，允许暂时没有可用库存               |
| 确认互换            | +数量  | 不变   | 再次检查所有物料的可用量，不足则整单保持待确认 |
| 拒绝待确认互换      | 不变   | 不变   | 申请结束                                       |
| 取消待确认互换      | 不变   | 不变   | 申请结束                                       |
| 取消已预留预约/互换 | −数量  | 不变   | 释放全部库存                                   |
| 标记领取            | −数量  | +数量  | 整单领取；重复操作不重复扣减                   |
| 手动现场发放／互换  | 不变   | +数量  | 只使用未预留库存，整单校验并防重复提交         |

- 可预约量 = 总数量 − 已预留 − 已领取，数据库约束保证不能为负。
- 所有状态和库存变更在 SQLite `BEGIN IMMEDIATE` 事务中执行；多个服务进程共享同一磁盘数据库时也串行校验写入。不是依赖前端余量数字防超额。
- 免费预约与互换分两种提交，一次选择多件物料时必须属于同一活动、同一制作人、支持同一方式；不同制作人分别预约。
- 每次选择生成 UUID 幂等键；同一键、同一内容重试返回原预约与查询凭证，不重复占用。相同键提交不同内容返回冲突。
- 免费预约失败不产生部分预约。后台确认互换也采用整单事务。
- 取消、拒绝后的预约不会恢复；要重新预约。重复取消/确认/领取同一目标状态返回当前结果；不允许已领取后取消、待确认时领取、拒绝后确认。
- 总量可修改，但不能小于已预留与已领取之和；物料暂不删除，避免破坏预约记录。
- 本版整单核销，不能拆分领取；不支持撤销已领取。现场应先核对全部数量再确认。
- 活动结束日期/时间决定默认首页是否展示，按北京时间计算；物料可单独设置预约截止时间或暂停领取。两者均在后台阻止新请求，不取消、释放已有预约；旧互换申请仍可确认。没有自动过期、超时释放、每人全活动总上限或自动候补。
- 物料名称、图片、活动说明在预约查询里展示当前版本，预约数量不随物料编辑而变化。

## 限领与联系方式

- 限领按“同一活动内的一件物料 + 规范化联系方式”累计，包含待确认互换、已预留、已领取的数量；已取消与已拒绝不占限额。
- 规范化处理为 NFKC、去空白、转小写。它不验证联系方式真实性，也不识别同一个人使用不同联系方式的情况。
- 只做初步限领，不宣称能够彻底防止重复领取。不会按登录制作人账号限制免登录领取。
- 联系方式为必要的自由文本，可填写微信、电话或邮箱；不发送验证或通知。
- 联系方式和留言仅对应制作人与持有专属查询链接者可见。互换图片不放到公开文件目录；需制作人会话或对应查询凭证。

## 查询与现场领取

- 领取码是随机 10 位十六进制码，用于后台查找，不是私密查询凭证。
- 查询链接含由随机幂等键派生的不可猜测凭证，数据库只保存查询凭证的 SHA-256 哈希。随机猜测 UUID 或领取码无法访问预约。
- 持有私密链接即可查看及取消该预约，用户应保存且不要公开分享。丢失链接不支持自行通过领取码找回，请联系制作人核对。
- 领取操作只能由登录后且拥有对应预约的制作人在后台执行。加入同一活动不获得他人核销权限，站点管理员也不能处理他人预约。查询页没有核销权限。
- 不主动通知申请状态，领取者通过查询页刷新；预约不自动过期。

## 工程默认值

- 单站点、单服务器本地磁盘，SQLite WAL；不支持跨机器共享 SQLite 或多副本容器的各自本地数据库。
- 演示数据须显式执行 seed，演示标识不可通过普通编辑移除。正式环境应从空数据目录启动。
- 上传图片持久化保存。暂无未引用上传的自动清理、图片压缩或病毒扫描；后续需要按实际流量补充运营策略。
- 基础 IP 限流在单进程内生效，多副本正式部署需要在网关做统一限流；错误不回传数据库或密码信息。
- 没有邮箱/短信等外部服务依赖，没有支付与广告内容。

## 交给需求文档确认的问题

1. 已支持物料级截止；是否需要整场统一预约开始／截止、领取时段或多个领取点？场次是否需要结构化列表和别名？
2. 免费领取与互换是否应允许混合整单？互换是整单确认，还是按件协商？
3. 限领按人、联系方式、活动还是物料累计？待确认互换是否占限额？是否需要验证码？
4. 现场补录已支持；是否允许部分领取、撤销现场登记／核销、延期、自动失约释放或候补队列？
5. 联系方式字段是否固定为微信/电话之一，是否需双方交换联系方式与状态通知？
6. 一份预约何时可以由领取者编辑？调整数量或物料时如何处理原库存？
7. 单件转草稿隐藏已支持；是否需要独立的已发布草稿版本、活动归档、删除或批量导出？
8. 是否需要找回密码、注销账号、联系人保存时长和数据删除入口？
9. 多位制作人共享活动已支持；是否允许共同维护同一份物料清单、协作管理员？活动新增是否需要审核？
10. 最终品牌名称、正式内容、域名、预计峰值、部署地区、上传总额度和备份频率是什么？

这些待定问题不阻塞当前核心领取、互换与管理流程；应在确认后调整集中规则，而不是在页面中零散增加判断。
